# M127 完整 PCS 三后端对照：结果与建议

**四个代表点均以当前自研后端的流程总耗时最低。** 在本次实际接入下，暂不建议将生产默认实现改为 ark 或 FourQ C。自研算术保持冻结；这不是一次已经采用自研优化的实验。

32 线程，M127 二次扩域，μ=20/26、r=2、c=4、QA/RS。每点三个后端，各做三轮独立进程，顺序 ABC/BCA/CAB；每进程一次预热和三次测量，共 36 个进程、108 条正式记录。每次重新 Setup，均使用同一最新一次性内存生命周期。

流程总计 = commit + 正向表释放 + open + verify。open 已包含原消息释放和第一棵中间树的查询阶段。Setup、输入及求值、序列化、诊断和最终清理另列；把这些都计入完整 wall 后，四点仍以自研最低：ark 比自研增加约 10.94%–15.50%，FourQ C 增加约 14.56%–23.27%。

流程总计中，ark 相对自研多 15.34%–20.08%，FourQ C 多 21.94%–31.52%。每个点三个配对进程轮次的总计差值均为正，方向一致。样本标准差、范围和逐轮差值在 CSV 中提供；只有三轮独立进程，进程内的三次重复不是九轮独立样本。这里不作置信区间或显著性检验声明。

不能把这个总计结果扩展成“所有阶段都稳定更快”。例如 μ26 QA 的 ark commit 均值比自研多约 3.04%，但逐轮差值从 −38.1 毫秒到 +459.3 毫秒，跨零；部分 verify 均值也非常接近。结果表逐项保留这些差异。

完整 commit/open/verify、Setup/释放/清理、全程、证明字节与峰值内存见 [REPORT.md](REPORT.md)。RSS 同时给出“各独立进程峰值的均值”和“最大观测峰值”；μ26 三后端均约 28 GiB，未观测到有实用意义的内存优势。每点三个后端的参数 ID、承诺根、y₀、证明和后续挑战指纹以及编码大小完全一致。

这些结果测的是本次真实 PCS 接入，而不是仅比较裸算术。ark 使用同素数的通用 Montgomery Fp128 和原生 Fp2；FourQ 使用固定的 Linux/AMD64 UINT128 C 路径和原生扩域操作，经专用标量 FFI 接入。它们在实际编码边界的规范值导出，以及 FourQ 的 FFI 调用成本，都进入相应计时阶段。尚未单独剖析各项适配开销的占比，因此不能把全部差距归因于某一项。FourQ 的 ASM 或融合批量 PCS 接口不在本次对照中。

FourQ 内部 [0,p] 的冗余表示无需逐次规范化；边界和逆元合同依据 [Theorist 的完整算术核验](https://raft-artifacts.com/p/zkp-research/hyperfold-m127-representation-audit-2026-11-06)。工程适配与测试另由 Architect 独立审查。算术范围核验、正确性测试及性能数据均不构成 PCS 或 Fiat–Shamir 安全证明。
